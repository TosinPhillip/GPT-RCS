Here’s the clear, step-by-step overhaul plan to make your God's Peculiar Treasure School results portal truly **session-driven**, modular, and future-proof. Each step builds on the last, keeps the workflow smooth and redundancy-free, and ensures historical results remain accessible forever while current operations stay clean and focused.

1. **Define the Core Data Model Changes**  
   - Keep a single `students` collection for lifelong profiles (admission_number as unique key, name, DOB, contact, etc.).  
   - Add a new `enrollments` collection (or embed an array in students) for session-specific data: `{ student_id, session, class_, subjects: [...], status: "active"/"alumni"/"left", promoted: true/false }`.  
   - Tie `results`, `teacher_assignments`, `class_teachers`, and `student_subjects` explicitly to `session` and `term`.  
   - Add a `sessions` collection: `{ name: "2025/2026", active: true, terms: [{name: "First", active: true}, ...] }`.

5. **Implement Bulk Promotion at Session End**  
   - Admin tool: "Promote Students" → select class or individual → auto-create enrollments in next session with incremented class (e.g., JSS3 → SSS1).  
   - Option to mark leavers as "left" (no enrollment in next session).

6. **Update Result Upload & Visibility Logic**  
   - All new results tied to active/current session & term.  
   - Visibility block remains per-student (overrides session).  
   - Alumni access old sessions read-only.


8. **Testing & Migration**  
   - Create a migration script to move existing data into session-specific structures (e.g., assume current data belongs to "2024/2025").
